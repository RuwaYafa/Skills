# Lecture preparation template

Use this as a flexible default, not a rigid report form.

## 1. Lecture identity
- Lecture/topic name
- Official sections
- Main sources to consult
- Where it sits in the course sequence

## 2. Teaching goal
State one central idea that should remain with students after the lecture.

## 3. Learning outcomes
Write 3-6 observable outcomes using verbs such as classify, translate, construct, justify, prove, disprove, compute, compare, or apply.

## 4. Scope decision
Separate:
- **Must teach today**
- **Useful if time permits**
- **Defer / self-study / omit**

Explain the tradeoff when scope is tight.

## 5. Prerequisite check
Identify prior ideas needed and give a 2-5 minute diagnostic question when useful.

## 6. 110-minute teaching arc
Use a table with approximate time, purpose, instructor action, student action, and resource/board/slide notes.

A common pattern is:
- 0-10: retrieval + motivation/hook
- 10-30: first core concept
- 30-50: guided examples and misconception check
- 50-60: short activity/checkpoint
- 60-80: second core concept or proof method
- 80-100: application + progressively harder practice
- 100-107: synthesis/retrieval
- 107-110: next-lecture bridge / buffer

Adapt timing to the topic. Do not force this exact split.

## 7. Teaching narrative
For each major concept include:
- intuition before notation;
- formal definition/theorem;
- what to say aloud;
- what to write on the board;
- what belongs on slides only;
- one question to ask before showing the answer.

## 8. Worked examples
Prefer a progression:
1. accessible definition-level example;
2. reasoning-heavy example;
3. computing/application example when natural;
4. one exam-style or transfer example.

Show not only the solution but how an instructor can guide students toward it.

## 9. Misconceptions and interventions
Use a table:
- misconception;
- symptom/student answer;
- diagnostic question;
- corrective explanation/example.

## 10. Application lens
Select only natural applications from CE, CS, AI, or Cybersecurity. Explain the mathematical connection rather than merely naming the field.

## 11. Active learning
Provide 2-4 short activities such as:
- predict before calculating;
- true/false with justification;
- find a counterexample;
- classify examples/nonexamples;
- translate English <-> symbols;
- repair an invalid proof;
- compare two solutions;
- trace code and connect it to notation.

## 12. Practice and assessment alignment
Suggest a small set of exercises grouped by purpose:
- concept/definition;
- procedural fluency;
- reasoning/proof;
- application/transfer.

When possible, identify textbook exercise numbers only after verifying them in the source.

## 13. Instructor watch-list
State the 3-5 moments where students are most likely to get lost, and what to do in real time.

## 14. Closing and bridge
End with:
- a 1-3 question exit ticket or retrieval check;
- the key sentence students should remember;
- how this lecture prepares the next lecture.

## 15. Optional slide storyboard
Include only when the user asks for slide planning. Give slide purposes and content flow, not a `.pptx`, unless the user explicitly requests a presentation file.
